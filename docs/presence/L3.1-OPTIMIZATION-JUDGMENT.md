# L3.1 — Optimization Judgment Depth

Teaches Studio OS which optimization observations actually matter to a business owner. The engine already observes ~90 things (L3, 28 providers); this milestone decides which become customer-facing intelligence — and it governs that decision by the ratified **Optimization Promotion Constitution** (`constitution/07-optimization-constitution.md`). No new providers, observations, evidence types, dashboards, reports, or scores. The goal is not completeness; it is calm.

## What changed

The ~40 optimization evidence types that L3 emitted-but-suppressed (parked on the `platform_roadmap` rule) are now **classified into 11 business-task judgment rules**, with audience chosen by ownership and shifted by edition. Downstream, each customer-capable rule gains a recommendation (the full contract) and a plain-language moment. The intelligence architecture (Evidence → Judgment → Recommendation → Moments → Concierge) is untouched — L3.1 is data added to its rule catalogs, exactly as the pipeline was designed to grow.

## Ownership routing → audience (the classification)

Every optimization observation belongs to exactly one rule; the rule's *audience mode* encodes who owns the fix (Constitution Parts 2–4). Grouped so **40 observations collapse to 11 business tasks** — never one judgment per observation.

## Promotion logic (default silence)

An observation surfaces to a customer only if its mode + edition resolve to `audience: customer`. Otherwise it is recorded and **suppressed** (auditable, never deleted) or routed to the operator. The suppression pass already enforces this: `audience: none` → suppressed; only `customer`/`operator` judgments flow to recommendations, and only `customer` recommendations become moments. Platform-owned issues on our editions resolve to `none` — **Law 24 in force: we fix them, silently.**

## Edition routing (audience shifts, evidence doesn't)

`audienceByMode(mode, plan)` — the same evidence, a different audience by rung:

| Mode | Monitor | Presence | Managed / Agency / Enterprise |
|---|---|---|---|
| knowledge | customer | customer | customer *(only the owner holds the fact)* |
| optimization | customer | customer | **operator** *(the studio does the work)* |
| platform | **customer** *(migration evidence)* | none *(silent — Law 24)* | none |
| infra | **customer** *(their own infra)* | operator | operator |
| dormant | none | none | none |

**The ladder law, verified:** customer interruptions *decrease* as Studio OS owns more — measured on a representative evidence set, Monitor = 10 customer tasks, Presence = 6, Managed = 5. Monitor is the one edition where evidence flips *toward* the customer, because it's their external site and everything is honest migration signal. `runJudgment` loads the plan once and passes it into the pure `judge()`; the resolved audience is stored on each judgment.

## Grouped recommendation & moment strategy

- **Recommendations** (one `REC_RULE` per interruptible rule) carry the full contract — evidence, business reason, expected benefit, effort, undoability, manual alternative always available, approval required. Implementation detail stays internal; customer copy lives only in moments.
- **Moments** template each customer-capable rule in the Direction-A voice (plain merchant words; the tone lint forbids SEO/schema/DNS/score/grade/%/exclamations/blame). The knowledge tasks are `needs_attention`/`opportunity`; the platform/infra ones are Monitor-only and framed as migration value.
- **Bundling** — mergeable optimization moments fold into ONE "a few improvements are ready when you are." The enumeration is capped at three named concerns, then "a few more small things," so a crowded site reads like a friend's shortlist, not an audit's inventory. The **three-moment law remains absolute.**

## Real-world evaluation (advisor, not audit)

Before declaring done, the full Monitor pipeline (real external fetch → providers → judge → recommend → moments) was run against real sites. Across a polished site, a minimal site, and a deliberately-bare one, **~34 raw observations collapsed to exactly 3 calm moments** each — business basics, foundations, and one bundled "a few improvements" — with no scores, no jargon, no red lists, and optional/"nothing is wrong" framing throughout. Verdict: it reads like a **trusted advisor**, not an SEO audit. One refinement resulted: the bundle enumeration was capped for calm.

## Tests

`tests/presence/optimization_judgment_test.mjs` — 16 checks: every optimization type in exactly one rule (none left on `platform_roadmap`); 40 → 11 grouping; the full edition matrix (Presence silent-platform / operator-infra / customer-knowledge; Monitor flips to customer; Managed moves optimization to operator; dormant never anyone); the ladder law (interruptions decrease up the rungs); silence stays suppressed-but-auditable; no jargon/score/blame in any customer copy; determinism. Regression green: judgment 23, recommendation 26, moments 23, evidence 25, optimization 33, optimization-engine 20; staging full-chain moments 29/29.

## What L3.1 did NOT do

No new providers/observations/evidence types; no dashboards, reports, or scores; no change to the Evidence/Judgment/Recommendation/Moments engines themselves — only their rule catalogs grew. Promotion beyond this (e.g. new destinations, richer AEO) is future work under the same constitution.
