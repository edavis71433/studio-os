## Implement later (deliberate deferrals)

- **Shared findings substrate** (one module owning contract/factory/sanitizer/sort for Reviewer + Guardian): merge opportunistically the next time either file is touched. Doing it now churns two stable, tested modules for zero behavior change.
- **Report reuse (~24h) instead of regenerate-on-open**: real cost win, but needs decision-aware staleness (a reused report must know about dismissals and edits since) — a small design, not a patch. Deferred with a shape: reuse when `created_at < 24h` AND no change events since, `force` on "look again."
- **Progressive Brand Profile intake**: no profile-editing UI exists yet in the room, so there is nothing to trim. When it's built, surface three fields first (words to avoid, personality, reading level).
- **`gbp_post` fold-in**: watch in practice; fold into the holiday card if it misfires.
- **Handoff round-trip awareness** ("you've worked on this since"): cosmetic, low priority.
- **Constitution amendment codifying "studio output is never evidence"**: the law is documented here and in the atlas docs; writing it into frozen constitution 05 belongs to the next ratified amendment window, not to a self-service edit.
- **Edition gating of studio tools**: the module boundaries make it a router-level gate whenever the commercial call is made. No code now.

## Rejected (with explanation)

- **Merging the Reviewer and Guardian engines**: rejected. Different grounding, different storage, different future entitlement potential. The customer-facing merge (implemented) removes the confusion; an engine merge would remove the separability that makes the surface merge safe.
- **Removing any studio subsystem**: all five pass the value tests (M9.5F §4).
- **Building AI Memory / Visual / Video / Document Intelligence**: out of scope by milestone law; roadmap dispositions stand as recommended in M9.5F §8 (dissolve / merge / remove / reshape respectively).
